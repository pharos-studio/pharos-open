# 后端架构清单（基金投资管理看板）

> 用途：对各个功能做**增 / 删 / 改 / 查**的检索地图。改某一块前，先在这里定位"它在哪个文件、读哪些配置/数据、调哪些外部接口"，再动手。
>   
> 约束：**零外部依赖**（纯 Node 内置 CommonJS，无 npm install）、**backend/server.js 只做路由/装配，业务逻辑全在 backend/engines/ 与 lib/**。

**买入日期口径（2026-09-17 定稿，改任何相关代码前必读）** —— ★★ **三个日期是两回事**（此前把 ②③ 压成同一个字段名 `confirmDate`，是认知陷阱；**该 deprecated 别名连同 `sessionFromConfirm` 已于 2026-09-17 一并删除**，`tradeDate` 上只剩 `nominalPricingDate` / `sessionFromPricingDate`，接口也不再下发 `confirmDate` / `navDate`。磁盘上的老记录仍被 `server.js` / `backfill.js` 当**定价日**读取 —— 那是数据兼容，不是接口协议）：

| 日期 | 字段 | 规则 | 参与份额计算？ |
|---|---|---|---|
| 下单日 = 申请日 T | `date` | 用户填写的日期 | 否（只是起点） |
| **成交净值日 = 定价日** | `pricingDate` | 15:00 前 = T 日；15:00 后 = 下一交易日；非交易日顺延 | **是 —— 份额只由它决定** |
| **份额确认日 = 到账日** | `settleDate` | 定价日 + 1 工作日（A股）/ + 2 工作日（QDII） | **否 —— 只是份额登记入账的时间** |

计算链：`date`+`session` →（`tradeDate.nominalPricingDate`）**名义定价日**（只跳周末，是候选）→（`navQuote.resolveQuoteOnOrAfter`）**真实定价日** = 该基金净值序列中**第一个 ≥ 名义日的日期**；再对它套 `tradeDate.settleNominalDate` + 同一次顺延 → **真实份额确认日**。★ 两条链路**共用同一个防呆上限** `MAX_ROLL_DAYS`：**定价日**顺延超限 → `pending` 交人工；**确认日**顺延超限 → 日期照给（仍取序列上的交易日，比名义日靠谱）但标 `settleEstimated`（界面「预计到账」），**绝不冒充确定值**。
- **「当天买就按当天净值」不是 bug**，是**未知价原则**（事后价法）：下单时你能看到的是**前一交易日**的净值（当日净值当晚才算出），但成交按**当日收盘净值** —— 基金公司要收齐当日申购款后才算得出来。
- ★★ **`legacyConfirmDate` 的 A股+1 / QDII+2 恰恰就是「份额确认日 offset」，当年被误用成了「定价日」** → QDII 白白多取一天。**见到 T+2 即可断定是旧口径遗留**（新口径最多 +1）；A 股的 legacy +1 ≡ 新口径「15:00 后」，两者同值、无法区分。
- **不需要节假日表**：这只基金自己的净值日期序列就是最权威的交易日历，还自动吃下 QDII 的境外休市差异。历史日期一查一个准；未来日期查不到 → `pending`（在途），当晚净值公布后自动落位（**不预测未来就不会预测错**）。
- **顺延上限 `tradeDate.MAX_ROLL_DAYS = 15` 自然日**（防呆保险，非业务规则）：超过 → 保持 `pending` 交人工确认，绝不拿隔了很久的净值硬算份额。**实测依据**（008163/018391/016452/018966 各约 900 个交易日逐自然日枚举）最大顺延 **10 天**（下单 2023-09-28 选「15:00后」→ 名义 09-29 → 真实 **2023-10-09**）；最长连续无净值 11 天。**7 天会在国庆/春节卡死，是最小安全值 11、取 15 留余量。**
- **副作用（有意）**：下单日非交易日时，前/后两档会**收敛成同一结果**（那天根本没有 15:00 这个分界）→ `previewPurchase` 返回 `converged:true`，前端把两行合并成一句「非交易日下单，15:00 前后无差别：X 的净值」（开关保留、不隐藏不置灰）。★ 判据必须**两档都 `ok`**：长期停牌时两档也都 pending 且日期相同，那种「收敛」会误导。
- **落盘纪律**：`pricingDate` / `settleDate` 一律只写**真实解析值**（解析到了才写，否则 `null` 交给 `backfill`）。**绝不用名义日冒充**（旧实现那样做会把在途记录显示成错日期）。已确认份额（`shares != null`）的记录 `backfill` 第一行就跳过 → 91 笔历史零影响；`legacyConfirmDate` 永久冻结在 tradeDate.js。
- ★ **硬不变量**（`verify_trading_calendar.js` C9 有断言）：**份额只依赖 `pricingDate` 的净值，与 `settleDate` 完全无关** —— 把 `settleDate` 改错，`shares` 必须一个字节都不变。

**HTTP 路由（backend/server.js）**：`/api/state`（含只读旁挂 `navMeta`＝各笔买入的**定价日 + 份额确认日**；取值优先级 `p.pricingDate → 旧名 p.navDate/p.confirmDate → legacyConfirmDate`（旧字段名**只用于读磁盘老数据**；接口与落盘一律只认 `pricingDate` / `settleDate`）。两个标记**不可混用**：`inferred`＝定价日是推定值（老记录无任何日期字段），`settleInferred`＝确认日只是名义值（未落盘，用 +1/+2 工作日粗算））· `/api/refresh` · `/api/advice?session=am|pm` · `/api/timing` · `/api/nav-on-date?code=&date=` · `/api/purchase-preview?code=&date=&session=&amount=`（买入预览，只读免鉴权，一次返回前/后两档 variants + `converged` + 每档 `pricingDate`/`settleDate`）· `/api/fund-lookup` · `/api/fund-list` · `/api/theme-map` · `/api/stock-industry` · `/api/backfill-pending`（POST）· `/api/save`（POST，X-API-Key 鉴权）· `/api/purchase`（POST，X-API-Key 鉴权；含 add / 补填 / edit / delete 四态，落盘 `pricingDate` + `settleDate`）· 静态托管 `public/`。

## 6. 增删改查速查（最常问）

**➕ 新增一只基金**
1. `holdings.json` 的 `funds` 加项（必填 `code/name/category/market`；A股加 `estimateIndex`（如 `sz159834`），指数/商品基金加 `trackIndex`；`purchases:[{amount,shares,date}]`）。
   - **若 `category='broad'`，还要看是否该加 `caliber`**：`'cn'`=A股口径（默认，可省略）/ `'us'`=海外口径（用 `signals.broadGlobal` 那套阈值 + 美债 ERP）。漏填会被当作 `cn` 处理 → A股那套 25/80 + 中债 ERP 套到海外标的上，**不报错但结论失真**。
2. 若 `trackIndex` 不在 `DANJUAN_INDEX`/`LEGU_INDEX` → 在 `backend/fetchers.js` 加映射（否则估值走价格分位兜底）。海外宽基还需要 `fetchIndexPeHistory` 能取到该指数的 PE 历史（蛋卷 `pe_history/{code}?day=all`），否则回撤通道失效。
3. 若是 ETF 联接、自身无个股持仓 → 在 fund 上设 `penetrationProxy`（同指数基金 code）做穿透代理。
4. 若每日限购 → `config.dailyLimits[code]` 设数字/`0`(暂停)。
5. 若属某信号线，确认 `backend/engines/registry.js` 的 `scope` 命中（category 或 code）；否则它不会出 L2 信号（这通常是想要的）。
> 纯加基金**一般不用改代码**。

**➕ 新增一条信号线（新类别/新算法）**
1. 在 `backend/engines/strategies/` 新建策略文件写 `buildXxxDecision(fund, valuationMap, config)`，`require('../kernel')` 调 `buildFundDecision({...}, {cheapBy:'...'})`（tech/gold/core 需额外 `require('../../lib/util')` 算 MA/回撤/分位）。
2. `backend/engines/registry.js` 的 `REGISTRY` 加一条 `{builder: decisions.buildXxxDecision, type:'xxx', label:'...', scope:'code'|'category'}`。
3. `backend/engines/advice.js` 的 `pushDecision` 加一段 `else if (dec.matrix._type === 'xxx') { ... l2.push(...) }` 做文案格式化（记得 `dec.matrix._type = reg.type` 已由循环赋值）。
> 第 2、3 步是**唯一必须改代码的两处**，新增类别信号线无需动循环。

**➕ 新增一个类别**
1. `categories.json` 的 `categories` 加 `{key,name}`（目标比例在 `config.json` 设）。
2. `config.categoryPolicy[key]` 设 `'buy'`（参与分配）或 `'frozen'`（只持有不新增）。
3. 若需专属信号线 → 走上一条。

**✏️ 改估值倾斜 / 信号阈值 / 预算 / 限购 / 底仓**
- 估值倾斜：`config.signals.valuationTilt`
- 科技/黄金/红利阈值：`config.signals.{tech,gold,dividendYield,ma250,peGate}`
- 月度预算：`config.monthlyContribution`
- 每日限购：`config.dailyLimits`
- 防守仓：`config.defensive`
- 穿透赛道映射：`data/config/theme_map.json`（股票→赛道 + 别名；新股/新赛道在此补一条即生效，零代码改动；引擎未命中自动归「未分类」并列入 `penetration.unmapped` 提示补表）
> 以上**只改 data/config/config.json，零代码改动**。

**➖ 删除一个功能**
- 删信号线：`backend/engines/registry.js` 删对应 REGISTRY 条目 + `advice.pushDecision` 删对应分支（纯展示则仅此两处）。
- 删类别：`target.json` 移除 + `categoryPolicy` 移除。
- 删基金：`holdings.json` 移除（注意若它是某穿透代理的 `penetrationProxy` 源，需同步改被代理基金）。

**🔍 查"某计算用的是什么值"**
- 统一分配结果：`buildAnalysis().plan`（即 `a.plan`），前端与 advice 共用。
- 某基金当前估值：`f.valuation`（analysis 已拼好 PE 分位/价格分位/recent20dChange/source）。
- 缓存命中与否：fetchers 三个缓存单例 + `holdings_cache.json`（清缓存=删 `holdings_cache.json` 或重启进程）。

## 7. 架构约定（改码前必读）
- **单一真相源**：资金分配只走 `computeAllocation`；决策信号只答"加仓/不动"二档，不算金额（金额交统一引擎）。
- **配置直读**：backend/server.js 与 engines 一律经 `config.getConfig()`/`getApiKey()`，**不要**直接 `store.readJSON('data/config/config.json')`，否则漏掉 env `FUND_API_KEY` 优先逻辑。
- **I/O 边界**：`lib/*` 与 `backend/engines/{alloc/*,decisions}` 纯计算无网络；网络只在 `backend/fetchers.js` 与 `backend/engines/{analysis,advice}`（经 fetchers）。
- **缓存单例在 fetchers 模块作用域**，不在 backend/server.js，避免多实例状态不一致。
- **失败路径均有兜底**（估值→价格分位→锚点；净值→快照兜底），不写 0、不崩。
- **`category` 管分块、`caliber` 管算法（2026-09-12）**：`category` 只有 4 值，是环形图分块 / 配置桶 / 穿透范围的唯一依据，**不要为了区分算法去扩 `category`**；算法口径一律走 `caliber`（`util.caliberOf(fund)`，缺省 `'cn'`）。同一个 `category` 下的不同 `caliber` 有**完全独立的阈值块**（`signals.broad` vs `signals.broadGlobal`），**严禁合并或互换**——数值差一个数量级，换了不报错、只出错结论。
- **量纲约定**：`matrix.erp` 等连续量在 matrix 里是**小数**（−0.0165），而 config 里 `erpHigh/erpLow` 是**百分数**（−1.5/2.1）。凡把 matrix 量送进 `relScale` 必须 ×100。`pePercentile/peRollingPct` 是 0~100 百分数，不需要换算——**同一个 matrix 里两种量纲并存，是历史坑，改码时逐个确认**。

## 8. 买入时机复盘模块（timing，2026-09-04 落地）

> 设计文档：《买入时机复盘模块-设计v2》v2.8（内部文档，未随开源发布）。目的：用系统自身开口/收回事件 × T+30 客观净值，检验 L2 判定（命中率/收回过早率），产出**算法修正候选，逐条经用户批准后人工落地**——引擎从不自动改自己。

**新增文件**
- `backend/engines/timing.js`：战役状态机（open/close 跃迁）+ 状态持久化 + buy 幂等补扫 + T+30 回填（异步）+ 两账统计/诊断细分/候选。导出 `{onDecide, buyScan, runBackfill, stats}`；`_forTest` 供单测注入内存 IO（`backend/scripts/timing-smoke-test.js`，30 断言）。
- `data/state/timing_state.json`：状态机游标（code → lastVerdict/campaignId/campaignOpenDate/lastAddDate/lastRun + baselineDate），随采集原子写。
- `data/state/timing_samples.json`：样本池（type: `advice-open` | `advice-close` | `buy`；open/close 成对共享 campaign.id；buy 仅跟单成效不进校准）。

**采集挂点（全 am 会话；pm 只陈述不改状态）**
- `advice.js`：REGISTRY 循环内 `!isPM` 收集 `decMap` → `!isPM` 块内（writeDecisionHistory 后）`timing.onDecide(decMap, cfg)`（try/catch 非致命，不阻塞决策主流程）。
- `server.js`：启动（listen 回调）buyScan、`/api/advice` 返回前 buyScan、`/api/purchase` 成功后 buyScan。
- 首采日只建基线不记样本（防伪开口）；无定时器 → 采样节律=访问驱动（用户拍板），漏访样本标 `approx`。

- `GET /api/timing`（只读）：`stats()` 先响应，`runBackfill()` fire-and-forget（in-flight 锁）——回填绝不同步阻塞。前端 review.js 每月 tab ①采集进度 / ⑤判定校准 / ⑧跟单成效 三面板消费。

**参数（`config.json` 顶层 `timing` 段，全外置）**
- `holdDays` 30 交易日（终判，朴素裁判=T+30 正收益）· `previewDays` [5,10] 粗判 · `gapDays` 3 自然日（收回断链）· `weakN` 5 / `strongN` 10 / `strongHitRate` 0.65（准生证）· `historyStart` '2026-09-01'（此前的 buy 标历史定投、不重算）。
